This is a critical step! Connecting to the database is like building the physical plumbing for your entire application. If that connection fails, nothing else works.

Since you are using Node.js, we need to use asynchronous code (promises/`async`/`await`) because connecting to and querying a file takes time and must be handled carefully.

Here is a step-by-step guide with the actual code you should put into your `server/index.js`.

***

## 🛠️ Step 1: Preparation & Dependencies

First, make sure your server directory (`photo-gallery-project/server`) has the necessary dependencies installed.

If you haven't already, run this command in your terminal while inside the **`server`** folder:
```bash
npm install sqlite3 express cors dotenv
```
*   **`sqlite3`**: The library that allows Node.js to talk to SQLite databases.
*   **`express`**: Our basic web server framework.
*   **`cors`**: (Cross-Origin Resource Sharing) Necessary because the client and server run on different "origins" (though locally, it's good practice).

## 📄 Step 2: Writing `server/index.js`

Open your `server/index.js` file and replace any existing content with this structure. I have added detailed comments so you know what each section is doing.

```javascript
// server/index.js

const express = require('express');
const sqlite3 = require('sqlite3').verbose(); // We use the verbose version for better logging
const path = require('path');
const cors = require('cors'); 

// --- Initialization and Middleware Setup ---
const app = express();

// Use middleware: CORS allows your frontend to talk to this backend
app.use(cors()); 
// Tells Express to parse JSON requests coming from the client
app.use(express.json()); 
// Serves static files (like if we were serving HTML here, but not needed for pure API)

// --- Database Connection and Schema Creation ---

// The database file name. If it doesn't exist, sqlite3 will create it!
const db = new sqlite3.Database('./db.sqlite', (err) => {
    if (err) {
        console.error('🚨 Error connecting to database:', err.message);
    } else {
        console.log('✅ Successfully connected to SQLite database: db.sqlite');
        // 2. Schema Creation Function Call
        createTables();
    }
});

/**
 * Asynchronously creates the necessary tables if they do not already exist.
 */
function createTables() {
    // Use a helper function to run SQL statements safely in sequence
    db.serialize(() => {
        console.log('🏗️ Running schema setup...');
        
        // 1. Photos Table: Stores all the core gallery items
        db.run(`
            CREATE TABLE IF NOT EXISTS photos (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                url TEXT NOT NULL,     -- The URL path of the image
                caption TEXT NOT NULL, -- The descriptive title/text
                date TEXT NOT NULL    -- Date published (for sorting)
            );
        `, (err) => {
            if (err) {
                console.error('🚨 Error creating photos table:', err.message);
            } else {
                console.log('✅ Photos table is ready.');
            }
        });

        // 2. Users Table (Optional, but good practice for future expansion):
        db.run(`
            CREATE TABLE IF NOT EXISTS users (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                username TEXT UNIQUE NOT NULL,
                password_hash TEXT NOT NULL
            );
        `);
    });
}

// --- Server Routes (Placeholder for Phase 3) ---
const PORT = process.env.PORT || 3000;

// Simple health check route to confirm the server is running
app.get('/', (req, res) => {
    res.send('Photo Gallery API is operational!');
});


// This line starts listening for incoming requests from the client
const server = app.listen(PORT, () => {
    console.log(`🚀 Server running and listening on port ${PORT}`);
    console.log(`   Try accessing: http://localhost:${PORT}`);
});

// --- Cleanup (Optional but good practice) ---
process.on('SIGINT', () => {
    db.close((err) => {
        if (!err) console.log('\n✅ Database connection closed.');
        server.close(() => process.exit(0));
    });
});

```

## 📝 Explanation of the Code and Concepts

### 1. `sqlite3.Verbose()` and The Connection Block
*   **What it does:** We are calling the database connector and giving it a path (`./db.sqlite`). This tells Node: "Use this file as my memory." If the file doesn't exist, SQLite will create it for you.
*   **Why `(err) => {...}`:** Database operations are asynchronous. Instead of writing blocking code, we provide a callback function that executes when the database connection attempt finishes (either with an error or successfully).
*   **The Magic Variable (`db`):** The variable `db` now holds our active, connected instance to the SQLite database.

### 2. `createTables()` Function
*   **Purpose:** This wrapper function handles all the SQL commands needed to define the structure (the schema) of your data storage.
*   **`db.serialize(...)`:** This is crucial! It ensures that multiple SQL statements (`CREATE TABLE...`) are executed one after another, in order.
*   **`CREATE TABLE IF NOT EXISTS photos (...)`:** This line is the core of the setup:
    *   `IF NOT EXISTS`: This prevents your program from crashing every time you run it. If the `photos` table already exists, SQLite simply ignores the command and keeps running.
    *   **Columns:** We defined `id`, `url`, `caption`, and `date`. These columns are perfect because they cover all the necessary data points for a photo gallery.

### 3. Running the Code
When you run this server:
```bash
node index.js 
```
You should see output like:
```
✅ Successfully connected to SQLite database: db.sqlite
🏗️ Running schema setup...
✅ Photos table is ready.
✅ Users table is ready.
🚀 Server running and listening on port 3000
   Try accessing: http://localhost:3000
```

If you see those messages, **you have successfully connected to your database and initialized its structure!** The file `db.sqlite` should now exist in your `/server` directory.
