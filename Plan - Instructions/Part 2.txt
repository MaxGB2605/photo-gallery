# 🚀 Phase 2: Building the Brain & The Data Bridge
**(The Server Logic and API Integration)**

In this phase, we are going to build the `server` directory to act as the **API** (Application Programming Interface)—the "brain" that talks to the database. Your frontend JavaScript will stop looking at placeholder data and instead ask the server for the real photos!

### 🛠️ Pre-Flight Checks & Setup Review
Before writing code, ensure your project structure is ready:

1.  ✅ **Confirm Structure:** You have `photo-gallery-project/client/...` and `photo-gallery-project/server/...`.
2.  ✅ **Terminal Focus:** All actions below must start in the root folder (`photo-gallery-project/`).
3.  💡 **Mindset Shift:** Remember: The client (frontend) *cannot* talk directly to the database. It **must** talk to the server (backend), which then talks to the database.

### STEP 1: Initialize and Test the Server Skeleton (Node.js & Express)
*(Goal: Get a basic web server running.)*

1.  **Install Dependencies:** In your terminal, navigate to `photo-gallery-project/server` and install Express.
    ```bash
    cd server
    npm init -y # Create package.json if you haven't already
    npm install express sqlite3 body-parser cors
    # Note: We use 'cors' here later because the front and back are separate!
    ```
2.  **Create `index.js`:** Create a basic server file in `server/index.js`. This should be minimal code just to confirm Node is working and listening for requests.

### STEP 2: Database Connection (The Memory)
*(Goal: Establish the connection between the Node app and SQLite.)*

1.  **Database Setup:** In your `server/index.js`, use the `sqlite3` library to connect to `db.sqlite`. This file will be created automatically when you run the code.
2.  **Schema Creation:** Write the initial SQL logic (using the database connection) to create the required tables (e.g., a `photos` table with columns like `id`, `url`, `caption`, and `date`).

### STEP 3: Building Core API Endpoints (The Communication Lines)
*(Goal: Create specific routes/functions that accept requests and return JSON data.)*

This is where you define the "rules" of your application. You need at least two core endpoints:

1.  **`GET /api/photos`:** This route should query the database for *all* photo records and send them back as a structured **JSON array**.
    *   *(Example JSON output:* `[{ id: 1, url: '...', caption: 'Cloud', date: '...' }, { ... }]`)
2.  **`POST /api/photos`:** This route should accept data (photo details from the client) and then write that data into a new record in the database.

### STEP 4: Connecting Frontend to Backend (The Final Bridge)
*(Goal: Update your `client/js/main.js` file.)*

This is where the magic happens! You must rewrite any placeholder JavaScript logic.

1.  **Replace Placeholder Data:** In your `client/js/main.js`, delete any hardcoded photo arrays.
2.  **Use Fetch API:** Use the modern JavaScript `fetch()` API to make an asynchronous network request to the server's endpoint you created: `/api/photos`.
    ```javascript
    // Instead of using placeholder data...
    async function loadGallery() {
        try {
            const response = await fetch('http://localhost:3000/api/photos');
            const photosData = await response.json(); // Expecting JSON here!

            // Now, iterate through photosData and dynamically create the HTML elements on the page.
            displayPhotos(photosData); 

        } catch (error) {
            console.error("Error loading photos:", error);
        }
    }
    ```
3.  **Display Function:** Write a function that takes the data array from the server and iterates through it, generating the necessary HTML elements (`<img>`, captions, etc.) and injecting them into your `index.html` container.
